直接启动只接受当前平台检出字节对应的校验和，维持已发布行为。跨平台校验和换算仅用于覆盖导入的暂存库。

`PUBLISHED` 中的 8 使用本 fork 原始 LF/CRLF SHA-384，9 使用作者原始 SQL 的 LF/CRLF SHA-384。作者的 8 号校验和不会被当成 fork 的 8 号校验和接受，也不会擅自改成 9。

升级保留 `clipboard_items`、分组、来源应用与同步计数。已有列的原值保持不变，包含内容、内容哈希、时间、收藏、置顶、手工顺序、备注、分组和来源；较早版本仍按原已发布迁移补充缺失字段。旧 `image_ocr`、FTS 和触发器留在数据库中以保留旧派生缓存。9 号迁移创建独立的 `image_texts`、FTS 和触发器，不将旧 OCR 文本复制到新表。运行时使用作者系统 OCR，尚无 `image_texts` 记录的旧图片进入原生识别队列。

备份的“合并导入”是现有的按记录导入路径，不替换源迁移账，也不导入 OCR 派生表。上表描述的是整库覆盖导入和直接启动边界；本次没有新增作者数据库的通用转换能力。

- 本 fork 8 中已完成的旧 OCR 缓存及旧 FTS 保留，原图片留在原生识别队列，新 FTS 插入触发器可用。
- 两份原 8 SQL 的 LF/CRLF 校验和与 8/9 发布台账相符。
- 未知 8 校验和、作者原生 8 的直接迁移失败，不改迁移账或缓存。

执行这些测试使用临时或内存数据库，不需要打开本机生产数据库或剪贴板。
